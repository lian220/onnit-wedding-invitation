# 사진 저장소 비용 — 3차 분석

조사일 2026-09-03. 숫자는 전부 `claudedocs/storage-cost.py`가 만든다.
가격이 바뀌면 그 파일의 상수만 고치고 다시 돌리면 된다.

> **1·2차 분석은 값이 크게 과대했다.** "R2가 S3보다 115배 싸다"고 썼는데 틀렸다.
> CDN을 계산에 안 넣은 것이 원인이다. 무엇을 어떻게 틀렸는지는 4장에 적었다.

| 출처 | 무엇 |
|---|---|
| AWS Price List API (`AmazonS3/ap-northeast-2`, `AmazonCloudFront`, `AWSDataTransfer`) | S3 서울 · CloudFront 아시아 |
| [AWS 공지](https://aws.amazon.com/blogs/aws/aws-free-tier-data-transfer-expansion-100-gb-from-regions-and-1-tb-from-amazon-cloudfront-per-month) | CloudFront 무료분 1TB · 1,000만 요청 (영구) |
| <https://cloud.google.com/storage/pricing> | GCS 서울 |
| <https://developers.cloudflare.com/r2/pricing/> | R2 |
| <https://supabase.com/pricing> | Supabase |
| <https://www.backblaze.com/cloud-storage/pricing> | Backblaze B2 |

| **S3** 서울 | $0.025 | $0.126 | $0.0045 | $0.00035 | — |
| **GCS** 서울 | $0.023 /GiB¹ | $0.12 /GiB¹ | $0.01 | $0.0004 | — |
| **R2** | $0.015 | **$0** | $0.0045 | $0.00036 | 10GB · 쓰기 100만 · 읽기 1,000만 |

¹ **GCP만 GiB(2진)로 고시한다.** GB(10진)로 환산하면 실질 **$0.0214/GB · 아웃 $0.1118/GB**다.
² 월평균 저장량의 3배까지 무료. Cloudflare 등 Bandwidth Alliance 파트너 경유는 무제한 무료.

### CDN — 여기가 1·2차에서 빠져 있었다

| | 뷰어 전송 /GB | 요청 | 오리진 페치 | **무료분** |
|---|---|---|---|---|
| **CloudFront** (아시아) | $0.12 (첫 10TB) | $0.012 / 1만 HTTPS | **$0** (AWS 오리진) | **월 1TB + 1,000만 요청, 영구** |
| **Cloud CDN** (아시아) | ~$0.09³ | — | $0.01 | **없음** |
| **Cloudflare** (R2·B2 앞) | **$0** | $0 | $0 | — |
| **Supabase 내장** | 위 표에 포함 | — | — | Pro 250GB |

³ 아시아 캐시 이그레스는 공식 표에서 확인하지 못했다. NA/EU가 $0.08이고 아시아가 그보다
비싸다는 것까지만 확인했다. **$0.09는 추정치**이므로 GCS 열은 다른 열보다 신뢰도가 낮다.

**CloudFront의 두 줄이 결론을 뒤집는다.** 오리진 페치가 무료라 S3 이그레스($0.126)가
청구서에서 사라지고, 그 자리에 오는 CloudFront 요금이 1TB까지 $0이다.

## 2. 워크로드 모델

**청첩장은 한 번 쓰고 수백 번 읽는다.** 다만 그 "읽기"가 생각만큼 무겁지 않다.

| 값 | 근거 |
|---|---|
| 사진 60장 | 살롱드레터 상한 |
| 원본 **250KB** | 긴 변 1,600px WebP q80. 업로드 전 클라이언트에서 줄인다 |
| 썸네일 **12KB** | 3열 그리드용 240px WebP q75 |
| → **1건 저장 15.7MB** | |
| 링크 받는 사람 300명, **열람률 60%** | 받은 사람 전부가 갤러리까지 스크롤하지는 않는다 |
| 썸네일 **30장** 로드 | 지연 로딩. 화면에 들어온 것만 부른다 |
| 원본 **3장** 탭 | 60장을 다 열어 보는 사람은 없다 |
| 재방문 이그레스 **×1.05** | 사진 URL이 정적이라 재방문은 대부분 브라우저 캐시에서 나온다 |
| → **1건 이그레스 210MB, 요청 6,237회** | |

### CloudFront 무료분이 언제 끝나나

| 한도 | 소진 시점 |
|---|---|
| 요청 1,000만 | **월 1,603건** ← 이쪽이 먼저 막힌다 |
| 전송 1TB | 월 4,767건 |

**월 1,600건 아래에서는 이그레스가 통째로 $0이고 저장비만 남는다.**
그래서 트래픽 가정을 어떻게 잡든 청구서가 같다.

| 시나리오 (월 100건) | 1건당 이그레스 | S3+CF | R2 |
|---|---|---|---|
| 가벼움 (200명·열람 45%·썸네일 15·탭 1) | 41MB | $0.53 | $0.13 |
| **기준** (300명·60%·30·3) | 210MB | **$0.53** | **$0.13** |
| 무거움 (500명·80%·60·15) | 1,877MB | $0.53 | $0.13 |
| 이론상 최대 (500명 전원이 60장 전부, 1.5회) | 11,790MB | $22.01 | $0.13 |

**가벼움부터 무거움까지 전부 $0.53로 같다.** 45배 차이 나는 트래픽이 청구서를 안 움직인다.
CloudFront 무료분 안이라 이그레스가 0이기 때문이다.

## 4. 1·2차 분석이 틀렸던 것

### ① CDN을 안 넣었다 — 가장 큰 오류

정적 이미지를 CDN 없이 스토리지에서 직접 내보내는 구성으로 계산했다.
실무에서 그럴 이유가 없다. CloudFront를 붙이면 오리진 페치가 무료라
S3 이그레스가 사라지고, 뷰어 전송은 1TB까지 $0이다.

**"S3 $17.6 대 R2 $0.15, 115배"는 이 오류에서 나온 숫자다.**
CDN을 넣으면 $0.53 대 $0.13, 4배이고 절대 차액은 월 $0.40이다.

### ② 지연 로딩과 브라우저 캐시가 없었다

갤러리는 화면에 들어온 썸네일만 부르고, 사진 URL이 정적이라 재방문은 캐시에서 나온다.
그런데 "재방문 1.5회"에 이그레스를 1.5배 곱했다. 재방문의 추가 이그레스는 거의 0이다.

### ③ "무거움"이 무거운 게 아니라 물리적 최대치였다

하객 500명 **전원이 60장 전부를 원본으로** 받고 그걸 1.5번 반복하는 상황이다.
이제 그 값은 "이론상 최대"로 이름을 바꿔 참고용으로만 남겼다.

### ④ 썸네일을 30KB로 잡았다

3열 그리드 240px WebP는 12KB 쯤이다. 60장이면 1.8MB가 아니라 720KB다.

### 왜 진작 못 잡았나

**현실 감각으로 검산하지 않았다.** $162/100건이면 1건당 ₩2,240으로 판매가의 15%다.
실제 모바일 청첩장 서비스가 그런 원가로 돌아갈 리 없다. 그 이상함을 스스로 짚었어야 했다.

## 5. 결론

**이 규모에서 저장소 벤더 선택은 비용 문제가 아니다.**

월 1,600건 아래에서 1건당 원가가 ₩2~₩7이고 판매가의 0.05%다.
어느 쪽을 골라도 차이가 월 몇 달러다. **DX·운영·벤더 묶임으로 정하는 게 맞다.**

| 상황 | 선택 | 이유 |
|---|---|---|
| **지금 (데모)** | 아무거나 | 전부 $0. 지금 결정할 이유가 없다 |
| 백엔드를 Supabase로 갈 때 | **Supabase Storage** | README가 이미 지목한 경로. 벤더 하나. Pro $25에 포함 |
| AWS를 이미 쓸 때 | **S3 + CloudFront** | 월 1,600건까지 사실상 저장비만 낸다 |
| 월 수천 건 이상 | **R2** 또는 **B2+Cloudflare** | 이때부터 격차가 의미를 갖는다 (10,000건에서 5배) |

### 그래도 R2가 나은 한 가지

**비용이 트래픽과 무관해진다.** CloudFront는 1,600건을 넘는 순간 요청 과금이 붙고,
그때부터는 하객 수와 열람 습관에 청구서가 딸려 간다. R2는 그 축이 없다.
청첩장은 하객 수를 미리 알 수 없는 상품이라 이 성질에 값을 매길 수는 있다.
다만 **월 1,600건은 이 프로젝트가 당장 볼 숫자가 아니다.**

### 벤더보다 먼저 할 일 — 이건 안 바뀐다

원본 4MB를 그대로 올리면 저장이 **15.3배**, 이그레스가 **11.1배**가 된다.
S3+CloudFront 월 100건 기준 $0.53 → $7.28로, 무료분을 넘겨 요금이 발생하기 시작한다.

**긴 변 1,600px WebP로 줄이는 클라이언트 리사이즈(`canvas`)가 그 배수를 지운다.**
어느 벤더를 고르든 먼저 해야 하고 비용이 0이다. 위 숫자는 전부 이걸 전제로 한다.

### 확인해 둘 것

- **CloudFront 무료분은 요청이 먼저 막힌다.** 전송(1TB)보다 요청(1,000만)이
  3배 빨리 소진된다. 썸네일이 많은 갤러리라 요청 수가 크기 때문이다.
  썸네일 수를 줄이거나 묶으면 이 한도를 늘릴 수 있다.
- **R2는 프로덕션에 커스텀 도메인이 필요하다.** `r2.dev` 직결은 개발용이고,
  도메인 네임서버를 Cloudflare로 옮겨야 한다. 이게 실질적인 진입 비용이다.
- **스토리지 등급 최적화(Nearline·Glacier)는 무의미하다.** CDN을 붙이고 나면
  청구서가 거의 저장비뿐이지만, 그 저장비 자체가 월 $0.5 수준이다.
- **GCS 열은 신뢰도가 낮다.** Cloud CDN 아시아 캐시 이그레스를 확인하지 못해
  $0.09로 추정했다. 다만 무료분이 없다는 점은 확인했고, 그래서 소규모에서
  가장 비싸게 나온다.

### 덤 — 남은 세 가지가 한 번에 풀린다

README의 「남은 것」 중 셋은 전부 저장소 문제다. 세 조합 다 성립한다.

| 남은 것 | Cloudflare | Supabase | AWS |
|---|---|---|---|
| 갤러리 | R2 | Storage | S3 + CloudFront |
| 짧은 주소 | KV 또는 D1 | Postgres 테이블 하나 | DynamoDB |
| 방명록 · 참석 여부 | D1 | Postgres — README가 지목한 경로 | DynamoDB |
| 호스팅 | Pages | (GitHub Pages 유지) | (GitHub Pages 유지) |

데모 규모에서는 셋 다 월 $0에 가깝다. 벤더가 한곳으로 묶이는 것이 공통의 대가다.
