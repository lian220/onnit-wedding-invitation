## 2. 이 프로젝트의 형태

**청첩장은 한 번 쓰고 수백 번 읽는다.** 비용 구조가 여기서 결정된다.

가정 — 근거를 남긴다:

- 사진 60장 (살롱드레터 상한과 맞춤)
- 원본을 그대로 올리지 않는다. 긴 변 1,600px WebP ≈ **250KB**
- 썸네일 60장 × 30KB = 1.8MB
- → **1건 = 약 17MB**
- 하객 300명. 한 명이 썸네일 전체(1.8MB) + 원본 10장(2.5MB) = **4.3MB**
- → 1건당 아웃바운드 **약 1.3GB**, GET **약 21,000회**

## 4. 결론

**R2다.** 이유는 하나뿐이고 분명하다 — 이 워크로드는 이그레스가 전부인데 R2는 그게 $0이다.

읽기가 적고 AWS·GCP 생태계에 이미 묶여 있다면 S3·GCS가 맞다.
이 프로젝트는 둘 다 아니다.

### 확인해 둘 것

- **CDN을 붙여도 그림이 안 바뀐다.** S3 앞에 CloudFront를 세우면 오리진 이그레스는 줄지만
  CloudFront 아웃바운드(서울 $0.12/GB대)가 그 자리를 대신한다. GCS + Cloud CDN도 같다.
  R2는 Cloudflare CDN이 기본으로 앞에 서고 그 구간도 $0이다.
- **프로덕션에서는 R2에 커스텀 도메인을 붙여야 한다.** `r2.dev` 직결은 개발용이다.
- **리사이즈는 클라이언트에서 한다.** 업로드 전에 `canvas`로 긴 변 1,600px까지 줄이면
  변환 비용이 0이고, 위 가정(250KB)도 그때 성립한다.
  Cloudflare Images는 별도 과금이라 굳이 쓸 필요가 없다.
- **무료 한도는 계정 단위다.** S3의 100GB/월은 AWS 계정 전체 합산이라
  다른 서비스와 나눠 쓰게 된다. 위 계산에서는 보수적으로 빼고 잡았다.

### 덤 — 남은 세 가지가 한 번에 풀린다

README의 「남은 것」 중 앞의 셋은 전부 저장소 문제다.

| 남은 것 | Cloudflare로 |
|---|---|
| 갤러리 | R2 (무료 10GB) |
| 짧은 주소 | KV 또는 D1 — 지금 2,400자짜리 주소를 짧은 키로 |
| 방명록 · 참석 여부 백엔드 | D1 (무료 5GB) |
| 지금의 정적 호스팅 | Pages (GitHub Pages 대체, 무료) |

데모 규모에서는 **월 $0**이다. 벤더가 한곳으로 묶이는 것이 대가다.
